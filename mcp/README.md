# @aiengjobs/mcp

An MCP server exposing [frontierroles.com](https://frontierroles.com) — AI engineering
roles as tools an agent can call.

Every role is a first-party posting pulled straight from the employer's own ATS.
No sponsored placement, no recruiter reposts, and `applyUrl` always points at the
employer rather than an aggregator. Roles are dropped once they close or pass 90
days old.

## Tools

| Tool | What it does |
|---|---|
| `search_jobs` | Filter by text, skills, cluster, level, location, pay, freshness. Compact records, no descriptions. |
| `get_job` | One role in full, including its description and apply URL. |
| `get_company` | Every open role at one company (slug or display name). |
| `board_stats` | Counts and median USD pay across the whole board, grouped by skill, cluster, level, country, city, company or remote type. Takes the same filters as search. |
| `list_skills` | The controlled vocabulary — call this before filtering by skill or cluster. |

`board_stats` is the one worth knowing about. It aggregates over every matching
role rather than a page of results, so an agent can answer "what does this market
look like" instead of only "find me a job":

```
board_stats(dimension: "country", seniority: "senior+")
   820  US — median $228,268
   105  GB — median $174,577
   102  IN — median $53,589
```

## Install

Build it first (`npm run build -w @aiengjobs/mcp` from the repo root), then:

**Claude Code**

```sh
claude mcp add frontierroles -- node /absolute/path/to/aiengjobs/mcp/dist/stdio.js
```

**Claude Desktop / Cursor** — in the MCP config file:

```json
{
  "mcpServers": {
    "frontierroles": {
      "command": "node",
      "args": ["/absolute/path/to/aiengjobs/mcp/dist/stdio.js"]
    }
  }
}
```

Once the package is published to npm, both become `npx -y <package-name>` and the
absolute path goes away. The npm name is still an open decision — the `bin` is
currently `frontierroles-mcp`, but `@aiengjobs` is an unclaimed scope.

## Remote (Cloudflare Worker)

The same five tools over Streamable HTTP, for clients that can't spawn a local
process — claude.ai and ChatGPT in a browser.

```sh
npm run worker:dev -w @aiengjobs/mcp     # local, on :8787
npm run worker:deploy -w @aiengjobs/mcp  # manual deploy
```

CI deploys on any push to `main` touching `mcp/` (`.github/workflows/deploy-mcp.yml`).
It deliberately does *not* deploy on a data change: the Worker reads the board at
runtime, so the nightly site build updates what it serves with no deploy here.

| Route | |
|---|---|
| `POST /mcp` | The MCP endpoint. Also accepted on `/` for clients configured with a bare origin. |
| `GET /health` | `{ ok, jobCount, generatedAt }` — the board is the only dependency. |
| `GET /` | Plain-text explanation for anyone who pastes the URL into a browser. |

Stateless: every request builds its own server and transport, so there are no
Durable Objects and no session storage. The board is memoized at module scope, so
a warm isolate answers without re-fetching. Responses are JSON rather than SSE —
these tools return in single-digit milliseconds and never push anything
unprompted, so a stream would only hold a connection open and bill duration.

### Deploy credentials

Two GitHub secrets: `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`.

The token needs one permission for the current setup:

- **Account → Workers Scripts → Edit**

Adding a custom domain later (`mcp.frontierroles.com`) additionally needs
**Zone → Workers Routes → Edit**, **Zone → Zone → Read** and **Zone → DNS → Edit**,
and the zone has to be on Cloudflare. Cloudflare's "Edit Cloudflare Workers"
template covers all of these — scope it to the single account rather than all
accounts.

## How it gets its data

The site is the source of truth; this server holds no copy of the board.

- `GET /mcp-index.json` — the whole board minus descriptions (1.15 MB, ~0.19 MB
  gzipped), plus the skill taxonomy and FX rates. Fetched once per process and
  revalidated hourly with an ETag.
- `GET /mcp-jobs/<slug>.json` — one role with its description, fetched on demand.

Descriptions are ~95% of the corpus by size and are needed one role at a time, so
splitting them keeps a 25-result search at roughly 2k tokens instead of 30k. Both
files are generated by the nightly site build, so the server updates itself with
no deploy.

## Layout

```
src/board.ts   data access + caching   — no MCP types, no Node built-ins
src/tools.ts   what the tools do       — plain functions over a Board
src/stdio.ts   the protocol layer      — argument validation and serialisation
```

`board.ts` and `tools.ts` avoid Node-specific APIs on purpose: standing the same
tools up over Streamable HTTP on a Worker is a second file the size of `stdio.ts`,
not a rewrite.

Tests are at `tests/mcpTools.test.ts` in the repo root, run by `npm test`.

## Development

```sh
npm run dev -w @aiengjobs/mcp            # run from source with tsx
FRONTIERROLES_BASE_URL=http://localhost:4321 npm run dev -w @aiengjobs/mcp
```

`FRONTIERROLES_BASE_URL` points the server at a local build instead of production.
